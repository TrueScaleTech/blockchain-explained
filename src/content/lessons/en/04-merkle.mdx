## Hashing in pairs

Start from the transactions of a block and hash each one: these are the leaves. Join the leaves two by two and hash each pair, then do the same with the results, until a single hash is left: the Merkle root. Bitcoin uses double SHA-256 at every step.

The block header contains only the root, not the transactions. Because every hash depends on the ones below it, changing a single transaction changes its leaf, its parent and every hash up to the root, and the header no longer matches.

<Widget />

Pick a transaction: the filled nodes are its path to the root, and the amber ones are the proof, the sibling hashes needed to rebuild the root. Edit a transaction and its whole path changes.

## Proving one transaction without the others

To show that a transaction is in a block you do not need all the other transactions: the sibling hashes along its path are enough. Whoever checks hashes the transaction with the first sibling, the result with the next one, and so on. If the last hash equals the root in the block header, the transaction is in the block.

The proof grows with the number of levels, not with the number of transactions. The Bitcoin whitepaper calls this simplified payment verification: a light wallet keeps only the block headers and asks the network for proofs.

</Note>
